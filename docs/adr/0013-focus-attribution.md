# ADR 0013 · 特别关注的涨跌归因（窗口 + 逐标的贡献）

> 2026-10-29。关联：ADR 0008（合成日 K 的口径，本决策复用它的归一化与前向填充）、ADR 0005（价格序列统一总回报）、ADR 0009（市值与权重口径）。

## 背景

特别关注模块已有 20 根合成日 K 和「当日涨跌」，以及当日涨幅/跌幅最高的两只。但它回答不了**结构性问题**：
「这一天（或这一周、这 20 个交易日）组合涨了 X%，是少数标拉动的，还是普涨？谁在拖后腿？」
没有归因时只能逐只对照，既慢又容易误读（当天的权重 ≠ 区间开始时实际承担涨跌的权重）。

## 决策

### 1. 精确分解（可加总）

记窗口期初 t0 = 窗口第一根合成 K 的日期，参与者集合 P = t0 时**已有价格**的标的。
对每只 i ∈ P：

- `c0_i` = 最近一个 ≤ t0 的收盘价（前向填充，与合成 K 同一套指针语义）；
- `base_i` = 该标的**最新**收盘价（= 合成 K 的归一化基准「今收」）；
- `w_i` = 当前市值权重（折人民币、不折汇率，与 ADR 0008 一致）。

则

- 组合区间涨跌 `totalChange = Σw / value − 1`，其中 `value = Σ_i w_i·(c0_i/base_i)`
  （`value / Σw` 就是期初合成收盘 `V(t0)`，于是 `totalChange = 1/V(t0) − 1`）；
- 期初有效权重 `ω_i = w_i·(c0_i/base_i) / value`（区间内涨得多的标的，期初占比更小）；
- 自身涨跌 `change_i = base_i/c0_i − 1`（窗口日历口径，前向填充）；
- 贡献 `contribution_i = ω_i·change_i = w_i·(1 − c0_i/base_i) / value`。

**恒等式**：Σ_i contribution_i = (Σw − value)/value = totalChange。
它是代数恒等，不是近似；测试用 1e-12 断言。

### 2. 窗口

| 窗口 | 标签 | 合成 K 根数（含期初） | 覆盖交易日 |
|---|---|---|---|
| `.day` | 当日 | 2 | 1 |
| `.week` | 近 5 日 | 6 | 5 |
| `.month` | 近 20 日 | 20 | 19 |

可用根数不足时按实际根数；**少于 2 根不产出归因**（没有区间）。

### 3. 与 ADR 0008 的关系

- **同一套输入**：都来自 `FocusComposer.compose` 的 entries（当前市值权重 + 前向填充的收盘序列），
  所以「当日」归因的 `totalChange` 与合成 K 的 `dayChange` **逐位一致**（有测试断言）。
- **差异**：两张极值卡各自按「该标的最近两个观测点」算当日涨跌，不要求它在期初有价；
  而归因要求标的在 t0 就有价格 —— 窗口中途才第一次出现的标的**没有期初权重**，
  因此不进参与集、不产生贡献（恒等式仍然成立）。极值卡可能显示它的涨幅，归因里没有它：
  不是遗漏，而是「以什么权重参与期初」无法定义。
- 价格序列是**总回报口径**（ADR 0005 起 `prices` 存复权/累计净值），所以除息日不会在归因里显示为下跌。

### 4. 展示（View 只做展示，口径全部在 Core）

- 卡片标题「涨跌归因」+ 当日 / 近 5 日 / 近 20 日 分段选择器；
- 摘要：组合区间涨跌（含起止日期）、上涨只数与合计 pp、下跌只数与合计 pp、前 3 大集中度；
- 明细：名称 / 权重 / 自身涨跌 / 贡献 + 居中发散条（绿涨红跌，按最大 |贡献| 归一）；
  行可点击 → 跳「资产明细」并选中该标的（复用既有 `pendingAssetSelection` 意图）；
  超过 12 行折叠成「其余 N 只」合计行；
- 无新价（期初之后再没有观测）标「无新价」、自身涨跌显示「—」，贡献按 0% 计；
- 脚注写清公式与「当前市值权重、前向填充、未计汇率变动」；
- **隐藏数字模式（`hideNumbers`）下整页仍是 PrivacyPlaceholder**，归因卡不渲染。

### 5. 明确不做

- **不做汇率归因**：公式把汇率视为常数；真要做需要另一条 FX 序列并定义「汇率贡献 vs 价格贡献」，是另一个决策。
- **不按市场/池分组**：可在 Core 层加聚合而不用改公式，但目前界面不需要。
- **不做基准相对归因**（组合 vs 指数）。
- **不把贡献金额化**：金额随仓位规模变化，且会把绝对金额带进界面。

## 后果

- 归因是可加总的精确分解，用户可以放心把明细相加对照组合涨跌。
- 期初参与集为空（所有标的都在窗口中途才有价）、或合成 K 只有 1 根时，`attributions` 为空数组，
  视图整卡不渲染 —— 诚实降级，不编造权重。
- 中途新增标的在长窗口里不参与，可能让「近 20 日」的明细少几只；摘要里的只数反映的是参与集。
- 三窗口每次都算，成本与原合成 K 同阶（O(标的数 · 根数)），不引入新的数据库访问。

  恒等式对三个窗口都成立、当日 == `dayChange`、窗口起止日期、单根无归因、无新价 stale 且贡献 0、
  中途新增标的不进旧窗口、上涨/下跌拆分与只数、排序（并列按 assetKey）、前 3 集中度、全平 nil 集中度、窗口标签。
